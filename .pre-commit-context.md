# Pre-Commit - Contexto e Exemplos

Este arquivo fornece contexto adicional sobre como o pre-commit foi configurado neste projeto.

## 🎯 Objetivo

Garantir que todo código Terraform commitado no repositório atenda aos padrões de:
- **Qualidade:** Sem erros de sintaxe, formatação consistente
- **Segurança:** Sem vulnerabilidades conhecidas, sem secrets commitados
- **Boas Práticas:** Segue padrões de nomeação, documentação, estilo

## 🔧 Hooks Configurados

### 1. Terraform Validation
**Origem:** `antonbabenko/pre-commit-terraform`
**O que faz:** Valida sintaxe Terraform
**Quando falha:** Se houver erros de sintaxe em arquivos `.tf`
**Exemplo de erro:**
```
Error: Invalid resource name

  on terraform/bootstrap/cluster/main.tf:5, in resource "aws_s3_bucket" "":
   5: resource "aws_s3_bucket" "" {

A resource name is required.
```

### 2. Terraform Format
**Origem:** `antonbabenko/pre-commit-terraform`
**O que faz:** Formata automaticamente código Terraform (como `go fmt`)
**Quando executa:** Toda vez que há arquivo `.tf` alterado
**Modificação:** **SIM** - Modifica arquivos automaticamente
**Exemplo de correção:**
```hcl
# ANTES
resource "aws_s3_bucket" "terraform_state"{bucket="state"}

# DEPOIS (após terraform_fmt)
resource "aws_s3_bucket" "terraform_state" {
  bucket = "state"
}
```

### 3. Terraform Docs
**Origem:** `antonbabenko/pre-commit-terraform`
**O que faz:** Gera automaticamente README.md para módulos Terraform
**Quando executa:** Após alterar variáveis ou outputs
**Modificação:** **SIM** - Cria/atualiza README.md em cada módulo

### 4. TFLint
**Origem:** `antonbabenko/pre-commit-terraform` + `.tflint.hcl`
**O que faz:** Lint avançado de Terraform com regras customizadas
**Quando falha:** Múltiplas razões (veja seção "Erros Comuns")

**Regras principais:**
- Nomeação em snake_case
- Comprimento máximo de linha (120 caracteres)
- Tags obrigatórias em recursos
- Documentação obrigatória de variáveis/outputs
- Módulos com source pinned

**Exemplo de erro:**
```
Error: terraform_naming_convention: variable "clusterName" should be "cluster_name"
  on terraform/bootstrap/cluster/variables.tf:1
```

### 5. Checkov
**Origem:** `bridgecrewio/checkov`
**O que faz:** Análise de segurança Infrastructure as Code
**Quando falha:** Encontra configurações inseguras
**Configuração:** `.checkov.yaml`

**Exemplos de checks:**
- `CKV_AWS_62` - IAM policies muito permissivas (action: "*")
- `CKV_AWS_63` - RDS sem criptografia
- `CKV_AWS_226` - S3 sem versionamento
- `CKV_AWS_227` - S3 sem access logging

**Exemplo de erro:**
```
Check: CKV_AWS_62: Ensure no IAM policies documents allow "*" as statement's actions
Check: CKV_AWS_21: Ensure all data stored in RDS is securely encrypted
  Passed checks: 5
  Failed checks: 2
  File: terraform/us-east-2/ssm/main.tf:1-50
```

### 6. Detect Secrets
**Origem:** `Yelp/detect-secrets`
**O que faz:** Detecta secrets acidentalmente commitados
**Quando falha:** Encontra padrões de secrets

**Padrões detectados:**
- AWS_ACCESS_KEY_ID
- AWS_SECRET_ACCESS_KEY
- PASSWORD
- API_KEY
- PRIVATE_KEY
- DATABASE_URL com senha

**Exemplo de erro:**
```
Detected secrets in staged files
File: terraform/bootstrap/machines/terraform.tfvars
aws_access_key = "AKIAIOSFODNN7EXAMPLE"
                   ^ AWS credentials detected
```

### 7. YAML Lint
**Origem:** `adrienverge/yamllint`
**O que faz:** Valida e limpa sintaxe YAML (para manifests Kubernetes)
**Quando falha:** Problemas de indentação, espaçamento, etc

### 8. Commitizen
**Origem:** `commitizen-tools/commitizen`
**O que faz:** Valida mensagem de commit (Conventional Commits)
**Quando falha:** Mensagem não segue formato

**Formatos válidos:**
```
feat(terraform/bootstrap): add cluster configuration
fix(terraform/us-east-2): restrict IAM permissions
docs(terraform): update README
chore(pre-commit): update hooks
```

**Exemplo de erro:**
```
Error: commit message doesn't follow Conventional Commits format
Expected: type(scope): message
Got: "update files"
```

## 🔴 Cenários de Falha

### Cenário 1: Erros Auto-Fixáveis

```
user$ git commit -m "feat: add resource"
       ↓
[1] terraform_fmt FALHA
    Corrige automaticamente:
    - Indentação
    - Espaçamento
    - Formatação
       ↓
[2] trailing-whitespace FALHA
    Remove espaços em branco
       ↓
Arquivo foi modificado!
user$ git add .
user$ git commit -m "feat: add resource"
       ↓
✅ Tenta novamente com arquivos corrigidos
```

### Cenário 2: Erros que Precisam Correção Manual

```
user$ git commit -m "feat: add iam policy"
       ↓
[7] terraform_tflint FALHA
    Error: terraform_naming_convention
    Variable "admin_role" should be "admin_role"
       ↓
user$ vim terraform/us-east-2/roles/variables.tf
# Corrigir nome da variável
       ↓
user$ git add terraform/us-east-2/roles/variables.tf
user$ git commit -m "feat: add iam policy"
       ↓
✅ Tenta novamente
```

### Cenário 3: Erro de Segurança

```
user$ git commit -m "feat: add ssm parameter"
       ↓
[8] checkov FALHA
    Check: CKV_AWS_62
    Error: IAM policy too permissive
    File: terraform/us-east-2/ssm/main.tf:15
       ↓
user$ vim terraform/us-east-2/ssm/main.tf
# Restringir permissions:
# actions   = ["ssm:GetParameter"]
# resources = ["arn:aws:ssm:*:*:parameter/prod/*"]
       ↓
user$ git add terraform/us-east-2/ssm/main.tf
user$ git commit -m "feat: add ssm parameter"
       ↓
✅ Tenta novamente
```

### Cenário 4: Secret Commitado

```
user$ git commit -m "feat: add aws credentials"
       ↓
[1] detect-secrets FALHA
    Detected secrets in staged files
    File: terraform.tfvars
    aws_access_key = "AKIAIOSFODNN7EXAMPLE"
       ↓
user$ git reset HEAD terraform.tfvars
# Remover arquivo do commit
user$ echo "terraform.tfvars" >> .gitignore
user$ git add .gitignore
user$ git commit -m "feat: add aws configuration"
       ↓
✅ Tenta novamente SEM o arquivo secreto
```

## 📈 Integração com CI/CD

Pre-commit pode ser integrado com GitHub Actions:

```yaml
name: Pre-commit

on: [pull_request, push]

jobs:
  pre-commit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-python@v4
      - uses: pre-commit/action@v3.0.0
```

Isso garante que todos os PRs passem pelas mesmas validações localmente.

## 🎓 Aprendizado

### Entender Regras TFLint

Para entender cada regra do TFLint:
```bash
# Ver documentação completa
tflint --help

# Executar apenas uma regra
tflint --only terraform_naming_convention

# Gerar relatório detalhado
tflint --format json
```

### Entender Checks Checkov

Para entender cada check do Checkov:
```bash
# Listar todos os checks
checkov -l --framework terraform

# Detalhe de um check específico
checkov -c CKV_AWS_62 --framework terraform
```

### Customizar Regras

TFLint é customizável via `.tflint.hcl`:
```hcl
# Desabilitar uma regra se necessário
rule "terraform_workspace_remote" {
  enabled = false
}

# Modificar comportamento
rule "terraform_max_line_length" {
  enabled = true
  length  = 150  # aumentar limite
}
```

Checkov é customizável via `.checkov.yaml`:
```yaml
skip-checks:
  - CKV_AWS_1  # Apenas se houver justificativa

fail-on-checks:
  - CKV_AWS_62  # Falhar sempre nesse check
```

## 🆘 Suporte

Se encontrar problemas com pre-commit:

1. **Verificar versões:**
   ```bash
   pre-commit --version
   terraform -version
   tflint --version
   checkov --version
   ```

2. **Reinstalar hooks:**
   ```bash
   pre-commit uninstall
   pre-commit install
   pre-commit install --hook-type commit-msg
   ```

3. **Testar manualmente:**
   ```bash
   pre-commit run --all-files
   pre-commit run terraform_validate --all-files
   ```

4. **Consulte:**
   - `PRE-COMMIT.md` - Guia completo
   - `.pre-commit-config.yaml` - Configuração
   - `.tflint.hcl` - Regras TFLint
   - `.checkov.yaml` - Regras Checkov
